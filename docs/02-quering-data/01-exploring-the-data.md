# Exploring the Data

本节开始实际编写 SQL，重点不是记住某条语法，而是建立一套查询数据时反复使用的基本习惯：先控制返回的数据量，再明确需要哪些列，并让查询表达清楚的排序规则。

## 1. 探索数据：`SELECT *` 与 `LIMIT`

`SELECT *` 中的 `*` 在这里表示选择表中的所有列。刚开始了解一张表、查看数据长什么样时，使用它很方便：

```sql
SELECT *
FROM users
LIMIT 10;
```

探索数据时应当加上 `LIMIT`。如果表中有大量记录，不加限制就可能把大量数据从数据库传回客户端，造成不必要的网络传输和资源消耗。先取少量记录，通常足以了解表的大致内容。

SQL 关键字写成大写还是小写，不影响查询执行。讲师个人偏好大写关键字，主要是为了让 SQL 结构更容易辨认。

---

## 2. 生产查询：只取实际需要的列

“不要使用 `SELECT *`”这条建议并非毫无道理。它背后的原则是：**只查询应用真正需要的数据**。

例如，应用只需要用户的姓名和邮箱，就明确列出这两列：

```sql
SELECT name, email
FROM users
WHERE id = 1
LIMIT 10;
```

这样 PostgreSQL 只需要读取并返回查询所需的列，避免把应用最终不会使用的数据也通过网络传回去。

因此，可以这样区分：

- **探索数据**：使用 `SELECT *` 很方便，通常配合 `LIMIT`。
- **手写生产 SQL**：优先明确列出需要的字段，避免无意义的数据传输。

### ORM 中的 `SELECT *`

ORM（Object-Relational Mapper，对象关系映射工具）让应用可以通过对象的方式与数据库交互，例如 Ruby on Rails 的 ActiveRecord、Prisma 等。讲师指出，ORM 通常会查询完整记录，以便填充完整的对象。

这在某些场景下是合理的：如果查询时只取了 `name`，ORM 返回的对象可能没有加载 `email`。

后续代码读取 `user.email` 时，可能把“这个字段没有被查询”误认为“用户的邮箱值为空”，进而触发错误的业务逻辑。

ORM 通常也提供字段选择能力，可以在明确知道只需要部分字段时缩小查询范围。

但要记住：**使用 ORM 并不意味着可以忽略 SQL**。

开发者仍然要对 ORM 最终生成的 SQL 负责，需要理解它发出了什么查询，以及查询是否合理。

这一点与使用 AI 生成代码类似：**代码由谁生成，不会改变提交和使用代码的人所承担的责任**。

## 3. 别名与可读性

可以使用 `AS` 为查询结果中的列指定一个更合适的名称：

```sql
SELECT
    name,
    email,
    created_at AS registration_date
FROM users
WHERE id = 1
LIMIT 10;
```

别名不仅可以用于原有列，也适用于拼接、计算等表达式。否则，表达式结果可能得到不直观的默认列名。

例如 `?column?`：

```sql
SELECT
    name,
    'username: ' || username AS display_label
FROM users
WHERE id = 1
LIMIT 10;
```

这里的 `||` 用于拼接字符串，`AS display_label` 则为拼接结果命名。

虽然 SQL 允许省略 `AS`，直接写成 `name f_name` 也能表示别名，但讲师建议明确写出 `AS`。代码多几个字符，却能让读者立即看出后面的名称是别名，而不是漏写了逗号或另一个列名。

这体现了本节强调的原则：**清晰是一种善意（Clarity is kindness）**。

查询不仅要能执行，也应该让团队成员和未来的自己容易读懂。

## 4. 排序：明确顺序，并处理并列值

如果查询没有 `ORDER BY`，就不要假设数据库会按照某个固定顺序返回记录。需要特定顺序时，应明确写出排序规则：

```sql
SELECT *
FROM users
ORDER BY name ASC
LIMIT 10;
```

- `ASC`：升序。
- `DESC`：降序。

升序 `ASC` 是默认方向，但讲师倾向于显式写出 `ASC` 或 `DESC`，这样读者不必依赖对默认值的记忆，就能直接看懂排序意图。

**只按一个可能重复的列排序，并不能决定并列记录之间的先后顺序。** 例如，两条记录的 `name` 都是 Aaron，它们在姓名排序中处于同一位置，数据库可以用不同顺序返回它们。

要让结果顺序更明确，**可以追加第二个排序字段作为进一步的比较条件**：

```sql
SELECT *
FROM users
ORDER BY name ASC, id ASC
LIMIT 10;
```

这表示先按 `name` 升序；姓名相同时，再按 `id` 升序。也可以让第二个字段采用不同方向：

```sql
SELECT *
FROM users
ORDER BY name ASC, id DESC
LIMIT 10;
```

这表示按姓名升序，且姓名相同时，`id` 从大到小排列。

多列排序可以逐层解决前一个排序字段无法区分的并列情况。

若需要稳定、可预测的结果，最后应使用能够区分记录的字段作为排序条件。

## 5. 基本查询结构

本节最后归纳了一个会反复出现的 SQL 查询模式：

```sql
SELECT columns
FROM table
WHERE conditions
ORDER BY sort_columns
LIMIT row_count;
```

各部分的职责是：

| 子句       | 作用                   |
| ---------- | ---------------------- |
| `SELECT`   | 指定要返回的列或表达式 |
| `FROM`     | 指定数据来自哪张表     |
| `WHERE`    | 指定需要满足的筛选条件 |
| `ORDER BY` | 指定结果的排序规则     |
| `LIMIT`    | 限制返回的记录数量     |

并不是每条查询都必须包含所有子句，但 `SELECT` 和 `FROM` 构成了最基本的查询结构，其他子句根据需求加入。

**本节要记住的不是某条固定 SQL，而是查询时的几个判断：** 

1. 探索时先少量查看；
2. 写生产查询时只取需要的列；
3. 给表达式和别名起清楚的名字；
4. 需要顺序时明确排序，并考虑排序字段重复的情况。
