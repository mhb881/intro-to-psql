# Querying Data — Filtering（数据过滤）

本节介绍如何使用 `WHERE` 子句筛选数据，重点包括相等、不等、范围比较，以及如何通过 `AND`、`OR` 和括号组合多个过滤条件。

## 1. 基本过滤条件

`WHERE` 用于指定查询条件，只有满足条件的行才会出现在查询结果中。

```sql
SELECT *
FROM users
WHERE name = 'Aaron';
```

最基本的过滤操作包括三类：

| 类型               | 运算符               | 含义                         |
| ------------------ | -------------------- | ---------------------------- |
| 相等（Equality）   | `=`                  | 值与指定内容完全相等         |
| 不等（Inequality） | `<>`、`!=`           | 值与指定内容不相等           |
| 范围比较（Range）  | `>`、`<`、`>=`、`<=` | 判断值是否处于指定范围的一侧 |

---

### 相等与不等

相等比较使用 `=`：

```sql
SELECT *
FROM users
WHERE name = 'Aaron';
```

不等比较有两种写法：

```sql
-- SQL 标准写法
WHERE name <> 'Aaron';

-- PostgreSQL 也支持的写法
WHERE name != 'Aaron';
```

两者在 PostgreSQL 中作用相同，都是筛选出 `name` 不等于 `'Aaron'` 的记录。`<>` 是 SQL 标准写法，`!=` 则更符合许多程序员的习惯。

---

### 范围比较

范围比较通过大于、小于及其等于形式，判断值是否满足某个边界条件。

```sql
SELECT *
FROM users
WHERE id > 10
  AND id < 20;
```

这里要求 `id` 同时大于 `10`、小于 `20`，因此筛选出的是 `10` 和 `20` 之间的记录，不包含两个边界。

比较运算符可以通过是否带有 `=` 控制边界是否包含在结果中：

| 运算符 | 含义       | 是否包含边界 |
| ------ | ---------- | ------------ |
| `>`    | 大于       | 不包含       |
| `>=`   | 大于或等于 | 包含         |
| `<`    | 小于       | 不包含       |
| `<=`   | 小于或等于 | 包含         |

范围比较不局限于数字列，也可以应用于日期和字符串列。例如：

```sql
-- 查询 2023-11-10 之前创建的用户
SELECT id, name, created_at
FROM users
WHERE created_at < DATE '2023-11-10';

-- 查询按照当前排序规则，小于 B 的名字
SELECT id, name
FROM users
WHERE name < 'B';
```

字符串比较遵循数据库使用的排序规则（Collation），因此不能简单地将它理解为所有情况下都按英语字母顺序排列。

## 2. 使用 `AND` 和 `OR` 组合条件

实际查询通常需要组合多个条件。SQL 提供两个常用的逻辑运算符：

- `AND`：两个条件都必须成立。
- `OR`：两个条件中至少有一个成立。

例如，查询 `id` 小于 `5` 或大于 `100` 的用户：

```sql
SELECT *
FROM users
WHERE id <= 5
   OR id > 100;
```

也可以组合多个范围条件：

```sql
SELECT *
FROM users
WHERE id <= 5
   OR (id > 100 AND id < 110);
```

这个查询表达的是：

- `id` 小于或等于 `5`；
- 或者 `id` 同时大于 `100` 且小于 `110`。

预期结果包含 `id` 为 `1` 至 `5`，以及 `101` 至 `109` 的记录。

---

### AND 和 OR 的优先级

SQL 中，`AND` 的优先级高于 `OR`。

例如：

```sql
SELECT name, status
FROM users
WHERE name = 'Sarah Johnson'
   OR name = 'Aaron'
  AND status = 'active';
```

这个查询并不是将三个条件简单地从左到右执行。由于 `AND` 优先级更高，它实际等价于：

```sql
SELECT name, status
FROM users
WHERE name = 'Sarah Johnson'
   OR (
       name = 'Aaron'
       AND status = 'active'
   );
```

也就是说：

- 只要名字是 `Sarah Johnson`，就会被选中，不论状态是否为 `active`；
- 如果名字是 `Aaron`，则还必须满足状态为 `active`。

但假设我们的真实需求是：**只查询 Sarah Johnson 或 Aaron，并且两个人的状态都必须是 active。**

那么应该明确使用括号：

```sql
SELECT name, status
FROM users
WHERE (
    name = 'Sarah Johnson'
    OR name = 'Aaron'
)
AND status = 'active';
```

此时逻辑关系就非常清晰：

1. 先判断名字是否为 Sarah Johnson 或 Aaron；
2. 再要求匹配到的用户必须处于 active 状态。

**核心原则：当 `AND` 和 `OR` 混合使用时，主动添加括号明确分组，不要依赖自己记忆运算符优先级。**

---

## 3. 为什么应该主动使用括号？

讲师特别强调了 SQL 查询的可读性和正确性。

括号的作用不仅仅是改变运算顺序，还能让查询的逻辑结构直接体现在代码中。

主要有三个原因：

1. **提高可读性：** 阅读查询时，可以直接看出哪些条件属于同一组，不需要额外推断运算符的优先级。
2. **减少逻辑错误：** 多个条件组合时，很容易因为优先级理解错误而得到意料之外的结果。
3. **方便团队协作：** 让其他开发者更容易理解查询意图，也降低后续修改时出错的风险。

讲师还指出，额外的括号不会带来实际的性能损失。PostgreSQL 会解析并处理 SQL 查询，增加用于明确逻辑分组的括号，不会让查询因此变慢。

当然，也不需要毫无意义地添加大量括号。重点是让**条件分组与实际业务意图保持一致**。
