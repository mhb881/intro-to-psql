# Overview of Course Structure

## 1. 学习目标：理解原理，而不是记忆语法

这门课会结合理论与实践，但学习重点不是记住 SQL 语法或各种操作细节。具体语法需要时可以查阅文档，也可以借助 AI 工具；对于数据库相关问题，官方文档仍然是重要的参考来源。

课程真正希望建立的是一套**理解数据库和分析问题的思维框架**：

- 理解数据库功能背后的基本原理。
- 遇到新问题时，能够把问题放进已有的概念框架中分析。
- 根据对原理的理解作出判断，而不是依赖背诵过的答案。

因此，学习时应优先弄清楚“它为什么这样工作、解决什么问题、适用于什么情况”，而不是追求记住所有命令和细节。

## 2. 实践环境与工具

课程会使用实际数据进行演示，相关数据可以下载到本地。运行和操作 PostgreSQL 有几种方式：

| 方式                  | 适用场景                                           |
| --------------------- | -------------------------------------------------- |
| Docker                | 希望在本地运行 PostgreSQL，且熟悉 Docker           |
| postgres.app          | macOS 用户希望使用相对轻量的本地 PostgreSQL 环境   |
| Supabase              | 希望使用云端托管的 PostgreSQL 数据库               |
| 课程平台的 SQL Editor | 希望直接在浏览器中编写并运行 SQL，无需自行配置环境 |

课程平台内置的 SQL Editor 连接的是真实的 PostgreSQL 数据库，并非模拟数据库或教学玩具环境。

如果需要图形化数据库客户端，可以选择：

- **TablePlus**：讲师最常使用、也最喜欢的客户端。
- **DBeaver、Postico、DataGrip**：同样可以作为替代选择。

课程演示主要使用 **Supabase Web UI**。数据库客户端的选择并不重要，关键是能够连接数据库、执行查询并观察结果。

## 3. 学习支持

学习过程中遇到问题，可以通过电子邮件联系讲师。讲师表示会尽力回复，帮助学员解决学习中的困难。

## 本节要点

- **学习方式**：建立原理和思维框架，不要把记忆语法当作学习目标；细节可以查文档。
- **实践方式**：可以选择 Docker、postgres.app、Supabase 或课程平台提供的 SQL Editor 来使用真实 PostgreSQL。
- **工具选择**：TablePlus、DBeaver、Postico、DataGrip 都可以，课程演示使用 Supabase Web UI。
- **遇到困难**：可以通过邮件向讲师寻求帮助。
